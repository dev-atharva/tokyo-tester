Workflow bundles make definitions portable; revisions make changes recoverable. They solve different problems and are designed to be used together.

## Portable bundles

Export produces a workflow bundle containing the graph, service configuration, and scenarios. Registry secrets are intentionally absent. A bundle can be reviewed in source control, shared with another workspace, or generated by an agent.

Clone when you want a new editable workflow based on an existing one inside the application. Export when the boundary is a file or another installation.

## Import and validation

Import validates the bundle before persistence. Unsupported service types, malformed scenarios, invalid edges, and contract violations are returned as diagnostics rather than being deferred to the runner.

Agent imports require a validation receipt tied to the exact normalized bundle and an idempotency key for safe retry.

## Immutable revisions

A revision freezes the workflow and scenarios at a meaningful point. Runs retain the definition they executed, while revision history lets authors describe why a change was saved.

Create revisions before significant image, topology, or scenario changes—not for every cursor movement.

## Restore safely

Restoring an older revision creates a new current revision; it does not erase the intervening history. The operation uses an expected-version guard so a stale browser or agent cannot silently overwrite newer work.

<Callout title="Restore is a mutation" kind="warning">
Inspect the target revision and confirm the current version before restoring. MCP marks this operation destructive and requires explicit user approval.
</Callout>
